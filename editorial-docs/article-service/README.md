# article-service API

Внешний адрес: `http://localhost:8080/api/articles`. В сети Compose: `http://article-service:8080`.

| Метод | Путь | Доступ | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/api/articles` | Без токена | `200`: массив статей, без пагинации |
| GET | `/api/articles/{id}` | Без токена | `200`: статья |
| POST | `/api/articles` | `AUTHOR`, `EDITOR`, `ADMIN` | `201`: созданная статья |
| PUT | `/api/articles/{id}` | Автор своей статьи, `EDITOR`, `ADMIN` | `200`: обновлённая статья |
| PATCH | `/api/articles/{id}` | Автор своей статьи, `EDITOR`, `ADMIN` | `200`: обновлённая статья |
| DELETE | `/api/articles/{id}` | Автор своей статьи, `EDITOR`, `ADMIN` | `204`, без тела |

Для записи нужен `Authorization: Bearer <accessToken>` из auth-service. `AUTHOR` меняет и удаляет только свои статьи, `EDITOR` и `ADMIN` — любые. ID автора берётся из `sub` токена.

## Тело запроса

POST и PUT требуют оба поля:

```json
{
  "title": "Заголовок",
  "content": "Текст статьи"
}
```

`title` — непустая строка до 200 символов, `content` — непустая строка. Строки из одних пробелов не допускаются.

PATCH принимает любое из этих полей. Отсутствующие поля и `null` не меняют статью, `{}` тоже допустим. Переданный `title` должен содержать 1–200 символов, `content` — хотя бы один. В отличие от POST и PUT, строки из пробелов проходят проверку PATCH.

## Ответ со статьёй

```json
{
  "id": 1,
  "title": "Заголовок",
  "content": "Текст статьи",
  "authorAccountId": 7
}
```

## Ошибки

| HTTP | `code` | Причина |
| --- | --- | --- |
| 400 | `Validation error` | Ошибка проверки полей запроса |
| 400 | `INVALID_JSON` | Некорректный JSON |
| 404 | `ARTICLE_NOT_FOUND` | Статья не найдена |
| 403 | `NOT_ENOUGH_RIGHTS` | Нет прав менять или удалять эту статью |

Формат обработанных ошибок: `code`, `message`, `errors`. Для ошибок полей `errors` содержит пары «поле — сообщение»; иначе это `{}` или `null`. Отклонение токена и роли на уровне Spring Security возвращает `401`/`403` без этого контракта.

При ошибке проверки полей `message` — `Request validation failed`, а `errors` содержит сообщения для каждого некорректного поля.
